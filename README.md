# 10秒チャレンジ ランキング

学祭の「10秒チャレンジ」用のリアルタイムランキングです。GitHub Pages で公開し、記録は Firebase Realtime Database に保存します。

- `index.html` … 来場者・モニター用のランキング（ログイン不要、QRコード付き）
- `staff.html` … 受付用の計測・登録画面（受付用アカウントでログイン）
- `config.js` … 設定（Firebaseの接続情報、桁数、外部ボタンのキーなど）
- `common.js` / `style.css` … 共通の処理と見た目
- `database.rules.json` … Firebase のセキュリティルール

## まずはデモモードで試す

`config.js` の Firebase 設定が空のままだと「デモモード」で動きます。記録はそのPCのブラウザ内だけに保存されます。

```
python -m http.server 8000
```

を実行して、ブラウザで `http://localhost:8000/staff.html` と `http://localhost:8000/index.html` を別タブで開くと、受付で登録した記録がランキングにすぐ出ます。

## 本番の準備

### 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ でプロジェクトを作成（Googleアナリティクスはオフで可）
2. 左メニュー「構築」→「Realtime Database」→「データベースを作成」
   - ロケーションは **シンガポール（asia-southeast1）** が日本から一番近いです
   - 「ロックモードで開始」を選ぶ
3. 「プロジェクトの設定」（歯車）→「マイアプリ」→ Webアプリ（`</>`）を追加
   - 表示された `firebaseConfig` の値を `config.js` の `firebase` にコピー
   - `databaseURL` が無い場合は、Realtime Database の画面上部に出ている URL を貼る

`apiKey` は公開されても問題ない値です（書き込みはルールで守ります）。

### 2. 受付用アカウントを作る

1. 「構築」→「Authentication」→「始める」→「メール/パスワード」を有効にする
2. 「ユーザー」タブ →「ユーザーを追加」で受付用のメールアドレスとパスワードを登録
3. 一覧に出る **ユーザー UID** をコピー

受付が何台あっても、このアカウントで共通ログインすればOKです。

### 3. セキュリティルールを設定する

1. 「Realtime Database」→「ルール」タブを開く
2. `database.rules.json` の中身を貼り付け、`ここに受付用アカウントのUIDを貼る` をコピーした UID に置き換えて「公開」

これで「誰でも読めるが、書き込み・削除は受付用アカウントだけ」になります。
アカウントを複数使いたいときは次のように並べます。

```
".write": "auth != null && (auth.uid === 'UID1' || auth.uid === 'UID2')"
```

### 4. GitHub Pages で公開する

1. GitHub で新しいリポジトリを作り、このフォルダの中身をすべてアップロード
2. リポジトリの「Settings」→「Pages」→ Branch を `main`、フォルダを `/ (root)` にして Save
3. 1〜2分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます
   - ランキング: 上のURL（QRコードはこのURLを自動で表示）
   - 受付: 末尾に `staff.html` を付けたURL

## 当日の使い方

1. 受付PCで `staff.html` を開いてログイン
2. モニター用PCで `index.html` を開き「全画面」
3. 挑戦の流れ: スタート → 10秒だと思ったところでストップ → 名前を入れて「登録する」
4. 入力ミスは「最近の登録」の「取消」を2回押すと削除

### 外部ボタン

`config.js` の `triggerKeys`（初期値 `F9`）のキーを押すと、スタート/ストップします。
どこにカーソルがあっても反応するので、キーを送るUSBボタンやフットスイッチに F9 を割り当ててください。
計測は「ボタンを押した瞬間」の時刻で行うので、画面の描画の遅れは記録に入りません。

### 桁数について

`config.js` の `digits` で 2（1/100秒）か 3（1/1000秒）を選べます。
3桁でも、キーボードやボタンの読み取りに数ミリ秒のブレがあるため、最後の1桁は同着を分けるための目安です。
3桁にしたときは、手元の市販ストップウォッチで測って手入力する運用は避け、受付画面のストップウォッチ（または外部ボタン）で計測してください。

途中で桁数を変えるときは、記録をいったん全部消してから変えてください（2桁で入れた記録と3桁の記録が混ざると公平でなくなります）。

## 注意

- Firebase の無料プラン（Spark）は Realtime Database の **同時接続が100まで** です。スマホでランキングを見ている人は、画面を閉じたり別のアプリに切り替えたりすると自動で接続を切るようにしてあります。
- ランキングは一般公開されます。挑戦者には本名ではなくニックネームを勧めてください。
- 学祭が終わったら、Firebase の「Realtime Database」→「データ」から `records` を削除すると記録を消せます。
